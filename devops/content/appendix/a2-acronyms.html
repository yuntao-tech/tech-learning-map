📖 参考页

考题很少写全称。题干里出现 MTTR、SPOF、eNPS 时， 认不出来就等于没读懂题。这一页只做一件事：三秒查到它是什么、归在哪一节。 最需要停下来读两遍的是两组 —— CD 与 VSM， 它们各有两个含义，且都被官方文件同时使用。

🎯 怎么用这一页
  • 徽章看的是「考纲收录状态」，不是重要程度。 ⭐ 考纲核心 = 该词或其全称逐字见于 DOFD v3.4 官方考纲术语表（Concept and Terminology List，67 条）； 📘 官方模块子项 = 见于 v3.4 课程大纲子项，或 v3.6 官方学习目标（后者叠加 🆕 v3.6 新增）； 🧭 延伸 · 非考纲 = 两处都未逐字收录。
  • 🧭 不等于不用看。SLO、DORA、KPI 这些词在真实工程里到处都是，只是官方没把它列成考点词条。 考试若出现，多半是当干扰项用。
  • 「所属小节」给的是该缩写被正式讲透的那一节，不是它出现过的所有地方。 个别 🧭 延伸 · 非考纲 条目只给出最相关的一节，该节未必展开讲解； 确实全站没有归属节的，此列写作「本站补充，未单列小节」。
  • 要查完整词条（不只是缩写）与它们的一句话定义，去 A1 术语表（中英对照）； 要查官方每一项落在本站哪一节，去 A3 考纲映射表； 本页每条徽章判据所依据的官方文件，逐份列于 A4 官方来源与参考文献。

考试最爱设的陷阱

一个缩写，两个含义

共同点是：两个含义都对，都是官方用词，靠上下文判断， 所以题干不会提示你「这里的 CD 指哪一个」——判据必须自己带着。

⚠️ CD · 差一道人工闸门
含义判据
Continuous Delivery
持续交付		 流水线尽头还有一道人工闸门：随时可以按需一键部署，但按不按由人决定
Continuous Deployment
持续部署		 没有人工闸门：通过全部自动化测试的版本自动进入生产

题干里出现「可以部署 / 按需部署 / on demand」→ 交付；出现「每一个通过测试的版本都自动部署」→ 部署。

这两条方向由 DOFD v3.4 官方样题答案键确认：依赖部署流水线实现「按需一键部署」的实践是持续交付； 自动部署每个通过单元、集成、用户验收与非功能测试的版本，属持续部署。 两个词条也都逐字列于 v3.4 官方考纲术语表。
完整辨析见 3.3 持续交付 vs 持续部署。

⚠️ VSM · 中文只差一个字
含义判据
Value Stream Mapping
价值流映射		 一次性的分析活动：画出当前状态、标注处理时间与等待时间、算增值比例、找浪费
Value Stream Management
价值流管理		 持续的管理实践：把工具链数据接起来，端到端持续可见，而不是画完就归档

题干里出现「画图 / 分析 / 识别浪费」→ 映射；出现「端到端 / 持续可见 / 平台」→ 管理。

Value stream mapping 逐字列于 v3.4 官方考纲术语表； Value Stream Management 属 v3.6 官方学习目标（PeopleCert 现行产品页），v3.4 术语表未收录， Blueprint 的 Related Frameworks 一栏写作 Value Stream Management: End-to-End。

分别见 4.6 价值流映射 与 3.9 价值流管理。

⭐ 一分钟回忆清单
  • CD 有两个：Delivery 留人工闸门，Deployment 不留。合写成 CI/CD 时指哪一个看上下文
  • VSM 有两个：Mapping 是画一次图，Management 是持续管。中文只差「映射 / 管理」一个词
  • DOWNTIME 是八项不是七项；七项那个助记叫 TIMWOOD，不是官方词条
  • MTTR 在术语表内，MTBF 不在 —— MTBF 是典型干扰项
  • eNPS 官方写法首字母小写；SAFe 末位小写
  • ITIL 是框架，ITSM 是学科；术语表收录的是 ITSM（IT service management）
