一、这套资料是什么，不是什么

三句话说清边界。这三条决定了后面所有页面的写法，也决定了你该怎么信任它。

它是具体含义对你意味着
以 DOFD v3.6 为基准的全考纲覆盖 基准认证是 DevOps Institute / PeopleCert 的 DevOps Foundation DOFD， 现行版本 v3.6。站内八章一一对应考纲八个知识域，逐节展开。 按侧栏顺序读完第 1–8 章，考纲范围就走完了一遍，不需要另找目录对照
考场带不进去的东西 DOFD 是开卷考试，但只允许携带官方 Learner Workbook 与 Quick Reference Guide。本站不是官方教材，不能带进考场。 本站的作用是把因果关系讲透，让你在考场上不需要翻书。翻书要花时间，60 分钟 40 题平均每题 90 秒。
明确区分「考纲内」与「延伸实践」 每个概念都标了出处档位。GitOps、Kubernetes、Team Topologies 这类真实工程绕不开、 但 DOFD 不考的内容，一律标为 🧭 延伸 · 非考纲，并集中收进「延伸工程实践」一章 （该章尚未交付，因此本页不给链接）。 不会出现「花两小时背了一个不考的东西」的情况
⚠️ 一句话记住开卷边界

开卷 ≠ 可以带任何资料（只有那两份官方文档），也 ≠ 不用记 （考的是一眼认出，翻书就来不及）—— 完整的允许与不允许清单、以及这条规则的官方出处， 见 0.2 考试全解 · 第四节「开卷到底允许带什么」。

二、知识点的六面模板

第 1–8 章里每一个知识点都是一张卡片，卡片被强制拆成六个面。 这不是排版花样 —— 它是一份检查表：只回答了「是什么」的概念，等于没学。 六个问题各自解决一类失败。

面它回答什么不写它会怎样
① 是什么 一句可以复述出来的定义，附英文原词 记住了中文译名，考卷上出现英文原词却认不出来
② 为什么存在 · 解决什么问题 这个概念出现之前的具体痛点场景 概念变成孤立名词，忘得极快。记住痛点，定义可以现推
③ 与相邻概念的区别 对照表，并点明最容易被混淆的那一点 按本站推断，相邻概念是干扰项最常见的来源，这一面直接决定得分
④ 工程中怎么用 具体场景与判断动作，允许出现工具名 停留在术语层，遇到情境题（题干描述一个组织的困境）无从下手
⑤ 考试怎么考 命题角度 + 干扰项长什么样 + 排除技巧 知识懂了，题还是错，因为不知道出题人在哪里设陷阱
⑥ 记忆要点 一句话锚点，整张卡压缩成一行 复习时只能从头重读，没有可以快速刷过的抓手
六面模板的划分为本站教学整理，官方文件未以此形式给出； 本表第三列「不写它会怎样」及关于干扰项来源的判断为本站教学推断，官方未公布命题规律。

两种读法。第一遍按 ①→⑥ 顺序走完，建立因果； 复习时只读 ③ ⑤ ⑥ —— 区别、考法、锚点。 ①②④ 在第一遍已经把因果种下了，复习时重读它们收益很低，还会挤占时间。

📖 举个例子

3.3 持续交付 vs 持续部署 是六面模板价值最明显的一节：这两个概念的定义都很短，真正决定得分的是 ③ 那张对照表 —— 「有没有人工审批闸门」这一条。第一遍读完六面，之后每次复习只看 ③⑤⑥ 就够了。

三、徽章体系速查

每个页面标题旁、每张知识点卡的头部都有徽章。它们回答同一个问题： 这条内容的官方分量有多重，你该花多少力气记它。 前四种是档位（互斥，每个主题只有一个），后三种是标记（正交，可叠加）。

徽章判据看到它该怎么处理
⭐ 考纲核心 主题词逐字出现在 DOFD v3.4 官方考纲术语表（Concept and Terminology List）的 67 条之内 必背。英文原词要能一眼认出，中文释义要能复述。这是分值最密集的一档
📘 官方模块子项 出现在 v3.4 课程大纲的模块子项里，但不在 67 条术语表内（如 The First Way、Chaos Engineering） 要懂，不必抠字眼。考试会考它的归属与作用，不太会考精确定义
📝 教学整理 本站为便于理解做的归类、对照、映射，官方文件未以此形式表述 当理解工具用，别当考点背。考试出现的对应关系以官方表述为准
🧭 延伸 · 非考纲 既不在术语表也不在模块子项，属他人理论或工程实践（如 GitOps、Team Topologies、Westrum） 备考期可以直接跳过。工作中有用，考试不会出
⚠️ 易混淆 正交标记。该主题存在一个高度相似的相邻概念 直接跳到该卡的 ③ 与相邻概念的区别，那张对照表就是为它准备的
📌 高频 正交标记。所在知识域题数占比高，或该概念在多章反复出现 时间不够时优先保这些。临考突击就沿着它走
🆕 v3.6 新增 正交标记。v3.4 之后由 PeopleCert 现行产品页公布的学习目标新增的内容 照常记。它是官方内容，只是晚于 v3.4 术语表 —— 用旧资料备考的人最容易在这里丢分
⚠️ 最容易读错的一组

🆕 v3.6 新增 不等于 🧭 延伸 · 非考纲。 可观测性、价值流管理、平台工程、AIOps、生成式 AI 用例这几项都带「新增」标记， 它们是官方考纲内容，会考；只是 v3.4 的 67 条术语表编成时还没有它们， 所以档位标的是 📘 官方模块子项 而不是「考纲核心」。 典型的例子是 3.10 平台工程 与 3.8 监控与可观测性。

四、来源标注怎么读

每一页末尾都有一段来源标注，把这一页的内容按四个级别归位。 之所以要做这件事，是因为一个绕不开的事实：

📖 为什么必须区分「官方原文」和「本站整理」

DOFD 公开可得的完整考试文件只到 v3.4（2022-05，含题数分布表、67 条术语表、官方样题）， 而现行考纲是 v3.6（2024-10 更新，2025-02-03 修订）。 v3.6 未公开重新发布权重表。 因此凡涉及题数占比、命题规律、概念之间的对应关系，本站只能沿用 v3.4 数据并做推断。 不把推断和原文分开写，读者就无法判断哪一句可以当成考点背下来。

级别含义怎么对待
A 官方原文。出自具名官方文件，注明文件名与版本，例如 「DOFD v3.4 Examination Requirements（2022-05）」「PeopleCert DevOps Foundation Blueprint」 可以逐字信任。Blueprint 的 DevOps 定义句、CALMS 五格描述、三步官方名称都在这一级
B 官方现行页面。出自 PeopleCert 现行 DevOps Foundation 产品页公布的学习目标 可以信任范围，不要抠措辞。v3.6 新增的七项内容都靠这一级确认
C 本站教学整理 / 本站推断。归类、对照表、命题角度分析、记忆锚点 理解用，不背。标注紧贴在该内容下方，不会只藏在页尾
D 延伸 · 非考纲。真实工程需要但 DOFD 不覆盖的内容 考前跳过，考后再看。正文会明说「不在 DOFD 考纲内」

还有一类特殊来源：DOFD v3.4 官方样题答案键。 它能证明「官方认为哪个答案是对的」，本站只陈述结论（例如「约束理论支持第一步」）， 不复制任何题干与选项原文。凡带这个标注的判断，可以当作硬结论记。

五、三种读法

场景路线一句话操作
首次学习
按章通读		 第 1 章 → 第 8 章，按侧栏顺序，每节六面走满，读完一章做该章 总结页的练习 先读完 1.1 定义 DevOps 和 2.1 三步工作法总览 这两节， 整套体系的主轴就建立起来了，后面的内容都是往这根轴上挂
临考突击
按权重		 按各知识域题数从高到低推进，权重表见 0.2 第二节 · 八大知识域题数分布； 逐日排期见 0.4 两周冲刺路径 沿 📌 高频 与 ⭐ 考纲核心 走， 每节只读 ③⑤⑥ 三面
复习查漏
按知识地图		 从首页知识地图看整条因果链， 哪一块讲不出因果就回到那一节 自测标准是能否不看页面讲出 ③ 的分界线 —— 讲不出就是没学会，讲得出就可以标记为学完

三种读法都不需要从头到尾按顺序执行。同一章的 总结页 收了本章的易混淆对比表与记忆锚点清单，是复习阶段性价比最高的入口。 不确定考试本身怎么回事，先看 0.2 DOFD v3.6 考试全解； 想先看整体结构再决定读哪块，看 0.3 全局知识地图导读； 需要一份带时间的计划，看 0.4 三个月学习路径。 导论四节建议按 0.1 → 0.2 → 0.3 → 0.4 的顺序过一遍，合计约 1 小时。

六、站点功能

功能在哪说明
侧栏导航 左侧；窄屏点左上角 ☰ 展开 全站八章 + 延伸 + 附录的完整目录，按考纲结构生成
面包屑 正文顶部 显示「首页 › 本章 › 本节」，随时知道自己在体系的哪个位置

明暗主题 右上角 ◑ 所有图表都按主题变量着色，暗色下同样清晰
打印 / 存 PDF Cmd + P（Windows 为 Ctrl + P） 打印样式会自动去掉侧栏与按钮，只留正文与图表
📖 关于数据

学习进度与主题偏好都存在你自己浏览器的 localStorage 里， 不上传任何数据，也没有账号系统。 换浏览器、换设备、清理浏览数据都会丢失进度；隐私模式下可能存不上，属正常。 整站是纯静态页面，离线打开同样可用。
