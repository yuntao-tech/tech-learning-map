## 四、六轮迭代的教训（避免重蹈覆辙）

**同一种事故发生了四次**：写作契约里写摘要而不是原文 → 校验 agent 按契约判定「无官方出处」→
作者删除或降级了**真实的官方内容**。

被误删过的包括：

| 被误删内容 | 真相 | 当时契约的缺陷 |
|---|---|---|
| Blueprint 官方定义句 | 逐字在 Blueprint 正文左侧 | §4.3 只列了六个色块名 |
| v3.4 三个量化收益百分比 | 逐字在 Course Description | §4 只收了模块大纲 |
| 「Concept and Terminology List」 | 官方逐字小节名 | §4.6 未给英文小节名 |
| CALMS 五格描述句 | 逐字在 Blueprint | §4.3 只列了五个字母名 |

另有一次**条数错误**：术语表实为 **67 条**，我从第一批起就写「66 条」，
一路继承六轮共 437 处引用，直到 A1 agent 逐条核对才发现。

**结论**：
1. **契约里放原文，不放摘要。** 任何官方文件，能逐字收录就逐字收录。
2. **§6.1 存疑上报、不删除** 是最后一道防线 —— 正是它保住了第 67 条术语。
3. **agent 上报的实质判断几乎每次都对**，错的是契约不完整。收到上报先回原始 PDF 核实，不要预设 agent 错。
4. **主控必须自己验，不能采信 agent 自述。** 有一次总编辑 agent 报告「样板节未改动」，
   实际它被改了两处 —— 靠 mtime 与 grep 才发现。这也是后来引入 git 的原因。

## 五、多 agent 工作流的有效结构

六轮下来稳定有效的结构：

```
写作契约（主控写，含全部官方原文）
   ↓
撰写（每节一个 agent，只能改自己那一个文件）
   ↓
双视角对抗校验（考纲准确性 / 一致性与技术质量，都要求「找错不是夸奖」）
   ↓
修订（允许驳回校验意见但必须写明理由）
   ↓
分章总编辑（跨节去重、术语统一、交叉引用、summary 对齐）
   ↓
主控独立核验（git diff + 机械审计脚本 + 抽读内容 + 浏览器渲染）
```

关键设计：

- **文件权限硬约束**：每个 agent 只能碰自己那一个文件。引入这条后越权改动归零。
- **两个校验视角必须分开且对抗**，合成一个会漏。
- **风格基准指向一个具体文件**（3.3），比抽象描述有效得多。
- **每批之前开分支，批次结束合并**，`git diff master` 是唯一可靠的核验手段。
- 网络故障会让 agent 批量失败（曾一次失败 41/65）。用 `resumeFromRunId` 重跑，
  已完成的从缓存回放，不浪费。

### 为什么主数据源是站内 A1/A2，而不是 WordMaster

WordMaster 的 DevOps 术语库（402 词条）是**英语学习**词表，收的是 `daemon` `shard` `flush` `prune`
这类工程实践词；本站的术语是 **DOFD 考纲概念**（Change lead time、Value stream mapping、Cultural debt、
Golden Circle）。实测两者只在 22% 的出现次数上重合。

本站场景是「学知识体系」不是「学英语」，所以：

- **主内容**取自 A1 的「一句话定义」+「主讲小节」，这是站内自己的权威措辞，覆盖 74%；
- WordMaster 只贡献重叠的 43 条，内容是日常义 / 字面 / 词源 / 易错点，**折进「更多」按钮，默认收起**。
  这 43 条已应用 WordMaster 的审阅修订（词源勘误后的版本），不是原始生成数据。

### 维护方式

内容改了之后重新生成即可，不联网、不调模型：

```bash
python3 tools/gen-glossary.py
```

生成器会做两件不能省的事：

1. **锚点校验** —— `href` 来自 A1（主讲小节）、`kp` 来自知识点标题，两者可能来自不同页面。
   若锚点不在目标页里就丢掉锚点、只留小节链接。首次生成时校出并丢弃了 11 个跨页错配。
2. **「更多」只允许整词精确匹配** —— 不把词组拆成单词去碰运气。
   否则「1st Way: Continuous Flow」会挂上 `continuous` 的日常义，那是英语层噪音，不是知识体系。

### 发音与检索（2026-09-04 追加）

**发音**。音标三个来源按可信度排序：人工确认的 DevOps 造词表（DevOps / GitOps / Kubernetes /
Microservices 等 21 个，通用词典查不到）→ WordMaster 已勘误的美音标注 → ECDICT 4.2 万词兜底。
ECDICT 的体例要归一：它拿西里尔字母 `ә`（U+04D9）当 schwa 用（出现 6700 多次），
重音记号用 `.` 和 `'`，一词多读写成 `li:d. led`——不处理会拼出 `/tʃeɪndʒ li:d. led taɪm/` 这种没法念的东西。

**逐词拼接只用于三个实词以内的短术语**，且不做词形还原。原因是实测发现：
`Goals` 还原成 `goal` 会读出单数 `/gəul/`，`families` 还原成 `family` 会读出 `/'fæməli/`，
句子式标题 `What is not a toolchain element` 拼出来是 `/hwɒt ai nɒt ei .../`——
全是看起来像模像样的错读音。含虚词（is/a/the/of/and…）的一律不给音标。
**宁可空着让朗读按钮兜底，也不能教错读音**，覆盖率因此从 46% 收到 29%。

**朗读**用浏览器内置的 Web Speech API，不联网、无依赖、`file://` 下可用，覆盖 100%。
发音人不能取列表第一个——macOS 的英语声音列表开头全是玩具音（Albert、Bad News、Boing、Bubbles…），
直接取第一个会拿到 Albert。改为白名单优先（Samantha / Alex / Google US English / Microsoft Aria…），
退回系统默认，最后才是排除玩具音后的任意一个。实测结果为 Samantha。

**检索**索引会去重：同一个概念常被索引三次（A1 收「Continuous delivery」、A2 收缩写「CD」、
知识点标题又收一次），按「中文名 + 落点」合并，保留信息最全的那条。
另外拆分并列术语时**只拆有空格的分隔符**：`Continuous Integration / Continuous Delivery`
是两个术语该拆，`Mean Time to Repair/Recover` 是同一个词的两种写法，拆了会产出
`Recover (MTTR)` 这种碎片当标题。生成器与运行时用的是同一条规则。
