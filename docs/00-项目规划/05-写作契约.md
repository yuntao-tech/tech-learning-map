## 1. 交付物

每个写作任务产出**一个完整的 HTML 文件**，路径由任务指定，例如
`content/ch02-core-principles/2.2-first-way-flow.html`。

**模板 = 现有样板节**：`content/ch02-core-principles/2.1-three-ways.html`。
直接复制它，只改以下四处，其余骨架（topbar / sidebar / crumbs / pager / script 引用）一个字都不要动：

1. `<title>` → `2.2 第一步：流动 · DevOps Foundation 学习站`
2. `<meta name="description">` → 本节一句话摘要
3. `window.PAGE={ch:"ch02", sec:"2.2-first-way-flow"};` → 换成本节的 ch / sec
4. `<main>` 内 `.page-head` 之后到 `<div id="pager">` 之前的正文

**不要**修改 `data/syllabus.js`（状态由主控统一翻转）。
**不要**新建 CSS / JS 文件，只用 `assets/css/components.css` 里已有的类。

## 2. 页面正文的固定结构

```
.page-head            —— kicker / 标题 / 英文名 / badge-row / lede
callout--info「🎯 本节要回答」  —— 3 条，对应本节最重要的三个问题
[主图 figure.dia]      —— 通常放在第一个知识点之前，用于建立空间感
article.kp × N        —— N = 2~4 个知识点，每个严格六面
[次图 figure.dia]      —— 嵌在相关知识点内部
divider-label「本节速查」
callout--exam「⭐ 一分钟回忆清单」—— 5~7 条
src-note              —— 本节来源标注
```

每节**至少 1 张自制 SVG**；概念关系复杂的节应有 2 张。

> **例外**：章节总结页 `summary.html` 不适用本节的 `article.kp` 六面结构，
> 按 [`01-阶段计划.md`](01-阶段计划.md) 第 35 行定义的总结页形态交付
> （总结图 / 易混淆对比表 / 记忆锚点清单 / 练习入口）；
> 其余骨架、§5 译法、§6 来源标注、§7 版权红线、§8 SVG 规范照常适用。

### 4.3 Blueprint 原文（可直接引用，注明出自 PeopleCert DevOps Foundation Blueprint）

**Blueprint 正文的定义句（逐字原文，可引为官方定义）**：

> With DevOps, people across the IT organization, working together, enable fast flow, feedback and
> continuous improvement of planned work into production, while achieving quality, stability,
> reliability, availability, security and team satisfaction.

中译（本站译文，标注为译文即可）：借助 DevOps，IT 组织中的各方协同工作，

同时达成质量、稳定性、可靠性、可用性、安全与团队满意度。

**这就是 DOFD 的官方 DevOps 定义**，可以直接引用。

- `2nd Way: Feedback`
- `3rd Way: Continuous Improvement (Experimenting and Learning)`

- `BENEFITS`：Improved release cadence, velocity, throughput, efficiency and stability,

- `Principles & Practices`：Frequent small releases using continuous integration, testing,

- `Related Frameworks`：Agile: Lean Development / ITSM: Processes / Lean: Reduce Waste /

### 4.10 图号与跨章链接

**图号格式固定为 `图 <章>-<节>-<序>`**，例如 2.4 节的第一张图是 `图 2-4-1`。
不要用章级连号（图 2-1、图 2-2、图 2-3…），那样每插入一节就要全章重编。
`figcaption` 开头写 `<strong>图 2-4-1　图名。</strong>`。

**跨章引用按目标是否已建成分两种写法**（用 `data/syllabus.js` 里该节的 `status` 判断）：

- 目标节 `status: "done"` → **直链该文件**，读者一步到位：
  `<a href="../ch02-core-principles/2.3-theory-of-constraints.html">第 2 章 约束理论（2.3）</a>`
- 目标节 `status: "todo"` → **链到章索引页**：
  `<a href="../ch04-frameworks/index.html">第 4 章 安全文化（4.5）</a>`
- ❌ `<a href="../ch04-frameworks/4.5-safety-culture.html">…</a>` —— 目标还没建成，会 404

新章交付后，主控会统一把指向它的章索引链接升级为直链，写作时不必操心。

**同章内**引用已建成的小节可以直接链到该文件；引用同章尚未建成的小节，写成纯文本不加链接。

## 6. 来源标注规则

页面末尾必须有一个 `.src-note`，说明本节引用了哪些官方内容。四级写法：

| 级别 | 写法示例 |
|---|---|
| A 官方原文 | 「出自 DOFD v3.4 Examination Requirements（2022-05）」 |
| B 官方现行页面 | 「出自 PeopleCert 现行 DevOps Foundation 产品页公布的学习目标」 |
| C 推断 / 教学整理 | 「本对照表为本站教学整理，官方未以此形式给出」——**必须紧贴在该内容下方，不能只写在页尾** |
| D 延伸补充 | 带 `badge--ext`，并在正文中说明不在考纲内 |

---

### 6.1 存疑时上报，不要删除（重要）

**如果你认为某个说法缺少官方出处：**

1. **保留内容**，按现有四级标注里最贴切的一级标注它（通常是 C 级「本站教学整理」）；
2. **把疑问写进你的返回报告**，说明是哪句话、你为什么存疑、建议核查哪份文件；
3. 主控回原始 PDF 核实后决定升级或降级。

**「出处待核」「待核实」「已提交主控」这类字样绝对不能出现在页面正文里。**
那是内部工作流，读者不需要看见，写进去只会制造噪音。上一轮因此在两章里堆了 72 处这种标记。

页面上只允许出现四种来源表述：A 官方原文（注明文件+版本）、B 官方现行页面、
C 本站教学整理 / 本站推断、D 延伸 · 非考纲。**没有第五种。**

已经连续三轮出现「契约漏记 → 判定无出处 → 删除或降级真实官方内容」的事故。
被误删过的包括 Blueprint 官方定义句、v3.4 量化收益、术语表官方英文小节名。
**删除是不可逆的，写进报告是廉价的。**

## 8. SVG 图表规范

- 放进 `<figure class="dia"><div class="dia__frame"><svg viewBox="0 0 W H" role="img" aria-label="…">…</svg></div><figcaption>…</figcaption></figure>`
- `viewBox` 必写，**不写 width / height**
- **颜色只用主题类**：`s-1..s-5`（描边）、`f-1..f-5`（填充）、`s-ink`、`s-muted`、`s-stroke`、`s-fill`、`s-fill2`。
  形状的 `fill` 可以写 `fill="var(--dia-fill-2)"`。**严禁写死 `#hex` 颜色**——否则暗色主题下不可读。
- 箭头用 `<defs><marker>`，marker 内的 path 用 `f-1`/`f-2`/`f-3` 类着色；不同颜色的箭头需要不同 id 的 marker，
  **id 在同一页面内必须唯一**（建议加节号前缀，如 `ah-22-1`）。
- 所有文本必须落在 viewBox 内，字号 ≥ 12。中文标签 15–17，说明文字 12–13。
- `figcaption` 以 `<strong>图 X-Y　图名。</strong>` 开头，然后写**这张图想让你看懂什么**，不要复述图里的字。
- 主题类的配色已按 WCAG AA 校准（`--dia-1..5` 在明暗两主题下对图框底色均 ≥ 4.5:1）。
  **只要不写死颜色，可访问性就自动达标**；一旦自造颜色，这个保证立即失效。

## 9. 语言风格

- 中文正文，考纲术语保留英文原词
- 不用「我们」「大家」「让我们一起」这类课堂腔
- 不写没有信息量的过渡句（「接下来我们看看」「总而言之」）
- 允许直白地指出常见错误做法，但不说教
- 句子短。一段不超过 4 行
- 避免 emoji，除 `face__label`、`callout__title` 中已约定的那几个
