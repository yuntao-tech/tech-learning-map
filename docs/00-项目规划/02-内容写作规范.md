# 内容写作规范

## 语言

- **正文中文，术语保留英文原词**。首次出现写成 `价值流映射 <span class="en">Value Stream Mapping / VSM</span>`。
- 练习题给**中英双语题面**（考试可能是英文，需要保持语感）。
- 不用「我们」「大家」这类课堂腔；不写空洞的口号句。

## 知识点六面模板

每个知识点是一张 `.kp` 卡，**六面缺一不可**：

```html
<article class="kp" id="kp-3-3-delivery-vs-deployment">
  <div class="kp__head">
    <div class="kp__id">kp-3-3</div>
    <h3 class="kp__title">持续交付 vs 持续部署<span class="en">Continuous Delivery vs Continuous Deployment</span></h3>
    <div class="badge-row">
      <span class="badge badge--core">⭐ 考纲核心</span>
      <span class="badge badge--warn">⚠️ 易混淆</span>
    </div>
  </div>
  <div class="kp__body">
    <div class="face"><div class="face__label">① 是什么</div> …</div>
    <div class="face"><div class="face__label">② 为什么存在 · 解决什么问题</div> …</div>
    <div class="face face--vs"><div class="face__label">③ 与相邻概念的区别</div> …对比表… </div>
    <div class="face"><div class="face__label">④ 工程中怎么用</div> …</div>
    <div class="face face--exam"><div class="face__label">⑤ 考试怎么考</div> …命题角度 + 干扰项套路… </div>
    <div class="face face--recall"><div class="face__label">⑥ 记忆要点</div>
      <p class="anchor-line">一句话锚点</p>
    </div>
  </div>
</article>
```

各面的写作要求：

| 面 | 要求 | 反例 |
|---|---|---|
| ① 是什么 | 一句可复述的定义 + 英文原词 | 抄一段词典式长定义 |
| ② 为什么存在 | 说清**它出现之前的痛点**。没有痛点就没有这个概念 | 「为了提升效率」这类无信息量的话 |
| ③ 与相邻概念的区别 | 必须是**表格**，且指出「最容易被混淆的那一点」 | 只罗列各自定义，不做对照 |
| ④ 工程中怎么用 | 具体场景。可以提工具名，但不写配置细节 | 「在实际工作中很有用」 |
| ⑤ 考试怎么考 | 命题角度 + **常见干扰项长什么样** | 「这个是重点，要记住」 |
| ⑥ 记忆要点 | 一句话锚点或助记结构，放进 `.anchor-line` | 把定义再抄一遍 |

## 徽章体系

**判据与逐字文案见[写作契约 §4.9](05-写作契约.md)，此处只做速查。**

| 徽章 | class | 逐字文案 | 用在哪 |
|---|---|---|---|
| 考纲核心 | `badge--core` | `⭐ 考纲核心` | 主题词逐字出现在 67 条官方术语表内 |
| 官方模块子项 | `badge--plain` | `📘 官方模块子项` | 在 v3.4 课程大纲子项内，但不在 67 条术语表 |
| 教学整理 | `badge--note` | `📝 教学整理` | 本站的归类、对照、映射，官方未如此表述 |
| 延伸 · 非考纲 | `badge--ext` | `🧭 延伸 · 非考纲` | 他人理论或工程实践，仅用于 `content/ext/` 与就地标注 |
| 易混淆 | `badge--warn` | `⚠️ 易混淆` | 正交，可叠加 |
| 高频 | `badge--hot` | `📌 高频` | 正交，可叠加 |

页头徽章取**本节主题词**的判定结果，不取节内最高级别条目。

## 图表规范

- **优先手写 SVG**，放进 `<figure class="dia">`，外层 `.dia__frame`，下方必须有 `<figcaption>` 说明「这张图想让你看懂什么」。
- SVG 内**不写死颜色**，一律用 `.s-1/.f-1 … .s-5/.f-5`、`.s-ink`、`.s-fill`、`.s-stroke` 等主题类，保证明暗主题都清晰。
- 用 `viewBox` + 不写 `width/height`，由 CSS 控制宽度自适应。
- Mermaid 仅用于时序图 / 状态机等自动布局确实合适的场景，且需本地 `assets/vendor/mermaid.min.js`。
- 每章至少 2 张自制图。**能画图就不要写三段文字**。

## 页面骨架

新建小节页时，复制任一已完成小节，只改三处：

```html
<title>…</title>
<script>window.SITE_BASE="../../"; window.PAGE={ch:"ch03", sec:"3.3-delivery-vs-deployment"};</script>
```

以及正文。侧栏、面包屑、上下页、进度按钮全部由 `nav.js` / `progress.js` 自动接管。

写完后把 `data/syllabus.js` 中该小节的 `status` 改成 `"done"` —— **这是唯一需要手动同步的地方**。
侧栏、章节页的小节列表、本章完成度、上下页链路都由 `nav.js` 在运行时从 `syllabus.js` 渲染，
不存在需要手工维护的静态目录。

**样板节**：[`content/ch02-core-principles/2.1-three-ways.html`](../../content/ch02-core-principles/2.1-three-ways.html)
是风格基准，新写小节直接复制它作为起点。
