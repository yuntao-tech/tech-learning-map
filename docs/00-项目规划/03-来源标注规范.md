# 来源标注规范

## 为什么要有这份规范

DOFD 的官方权重表只公开到 **v3.4**，而现行考纲是 **v3.6**。
这意味着资料里必然存在「官方事实」与「合理推断」的混合。
**把推断包装成官方，比不写更有害**——它会让人在考场上对错误的东西产生确信。

## 来源四级

| 级别 | 写法 | 示例 |
|---|---|---|
| **A 官方原文** | 注明文件名 + 版本 + 日期 | 「DOFD v3.4 Examination Requirements（2022-05）」 |
| **B 官方现行页面** | 注明来源页 | 「PeopleCert 现行 DevOps Foundation 产品页公布的学习目标」 |
| **C 推断** | 必须显式写「推断」 | 「v3.6 未公开权重，**推断**沿用 v3.4 分布，理由是模块结构一一对应」 |
| **D 延伸补充** | 带 🧭 徽章，单独成章 | GitOps、Kubernetes、Terraform |

页面上的呈现方式：

```html
<div class="src-note">
  来源：DevOps Institute《DevOps Foundation® Exam Study Guide》v3.4，
  Examination Requirements —— “Exam Topic Areas and Question Weighting”。
</div>
```

## 版权红线（不可逾越）

1. **不得复制官方样题原文**。DevOps Institute 的官方样题受版权保护。
   允许的做法：分析其命题角度、难度层级、干扰项构造方式，据此**自主命制**新题。
2. 所有练习题页面必须标注「**仿真题，非官方真题**」。
3. 不得复制官方 Learner Workbook / Quick Reference Guide 的成段文字。
4. 引用官方术语定义时，控制在必要长度内并注明出处；解释与展开必须是自己的话。
5. 图表全部自制，不复制官方图示。

## 版本变更应对

当发现官方发布新版本（如 v3.7 / v4.0）时：

1. 先在 `docs/00-项目规划/04-考纲调研记录.md` 追加一条**带日期和出处**的记录；
2. 更新 `data/syllabus.js` 的 `meta.version` 与受影响的章节结构；
3. 更新 `README.md` 的基准表；
4. 受影响的知识点加 🆕 徽章，被移除的内容降级为 🧭 延伸，**不要直接删除**——旧版考生仍可能需要。
