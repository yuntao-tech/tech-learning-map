小节 核心结论 记忆锚点 最易错点
2.1
三步工作法		 三步不是三条并列口号，而是有前置依赖的因果链；第三步是环绕前两步的土壤，不是第三支箭头。 向右流得快 → 向左反得快 → 绕着两者不停学。 把第三步画成流程的第三段；把 CALMS（价值观）当成三步（原则）的同义词。
2.2
第一步 · 流动		 让工作从左到右快速平稳流向客户：缩小批量、限制在制品、减少交接与返工，并且绝不把已知缺陷传给下游。 批量越大：排队越久、风险越集中、定位越难、越不敢回滚。 把流动窄化成「有一条跑得快的流水线」，忽略「不把缺陷传给下游」同样是第一步的硬要求。
2.3
约束理论		 整个系统的产出由那唯一的约束决定，改进非约束环节不会提升端到端产出。约束理论在本站的教学结构中服务第一步。 产出等于最细那段管子的流量，加宽别的段只是把水堵得更满。 约束和浪费混为一谈；把约束理论当成能同时回答「反馈怎么做」「学习怎么做」的完整框架。
2.4
第二步 · 反馈		 让信息从右到左快速回流到源头，在源头保证质量；问题一出现就蜂拥解决，而不是登记成工单排队等待。 第二步量的不是「有没有发现」，而是「隔了多久才发现」。 把「上了监控大屏」等同于有反馈；把同行评审归到第三步。
2.5
第三步 · 持续改进		 把改进变成日常工作的一部分：用实验和无指责事后复盘 Blameless postmortem，把一次局部经验转成全组织的能力。 官方叫「持续改进（实验与学习）」——学习是手段，改进才是目的。 与第二步混：反馈是「知道出了什么事」，第三步是「让同类事不再发生」。
2.6
混沌工程		 在受控条件下主动注入故障，验证系统与团队的真实韧性，把单点故障 SPOF 提前暴露出来。它在本站的教学结构中属于第三步（官方未把混沌工程正式归入第三步）。 故障一定会来，混沌工程做的只是把「什么时候来」的选择权抢回自己手里。 当成「随机搞破坏」；忽略它有假设、有爆炸半径、有中止条件。
2.7
学习型组织		 组织能持续把自身经验转化成行为改变：个人经验 → 团队知识 → 组织能力，唯一判据是「下次的默认做法变了」，不是「知道了」；前提是能安全地说出坏消息的安全文化。 学到了不是「知道了」，是「下次默认不会那样做了」。 把学习型组织与安全文化当成一回事；把「安全文化」理解成信息安全。
各节的官方名称与术语出自 PeopleCert《DevOps Foundation® Blueprint》与 DOFD v3.4 官方考纲； 本表的「核心结论 / 记忆锚点 / 最易错点」三栏切分方式为本站教学整理，官方未以此形式给出复习表， 「记忆锚点」一栏逐字取自各节 ⑥ 记忆要点面的锚点句，那些句子均为本站编写的助记语，不是官方表述。
易混淆汇总

本章丢分几乎都发生在下面这八对上。看这张表的方法是：先只读「分界线」一列， 能自己补出左右两边的，才算过关。

容易混的一对 分界线（最容易混的那一点） 一句话判据
第二步 · 反馈
vs
第三步 · 持续改进		 反馈解决的是「我现在知不知道出了什么事」；持续改进解决的是「下次同类的事还会不会发生」。两者都发生在事情出问题之后，所以最容易互换。 看时间指向：指向当下是第二步，指向下一次是第三步。
约束 Constraint
vs
浪费 Waste		 约束是决定整体产出上限的那一个环节，全系统只有一个在起作用；浪费是任何不为客户创造价值的活动，到处都是。消除非约束处的浪费，端到端产出一点都不会变。 问「去掉它，整体交付会变快吗」：会 → 约束；不会 → 只是浪费。
混沌工程
vs
故障演练		 混沌工程是带假设的实验：先声明「我认为系统能扛住 X」，再注入 X 去证伪，目的是发现未知；故障演练是按既定剧本走一遍已知预案，目的是验证预案和人能不能执行。 问「事先知不知道会发生什么」：不知道 → 混沌工程；知道 → 演练。
同行评审
vs
无指责事后复盘		 位置判据（门之前 / 门之后）2.1 kp-2-1-3 已给出，这里补一层跨节的：两者失效的方式不同。同行评审失效于「走过场签字」，补法在第二步内部（缩小变更、让评审快到能真看）；无指责事后复盘失效于「变成追责会」，补法在第三步之外的安全文化（2.7）——同一个坏结果，修的不是同一件东西。 看发生位置：门之前是第二步，门之后是第三步。
学习型组织
vs
安全文化		 安全文化是前提——人敢把坏消息说出来；学习型组织是结果——说出来的东西被吸收、传播、变成组织能力。有安全文化不一定有学习型组织，没有安全文化则一定没有。 安全文化 = 敢说；学习型组织 = 说了之后组织真的变了。
周期时间 Cycle time
vs
平均恢复时间 MTTR		 方向判据（交付 vs 恢复）2.1 kp-2-1-3 已给出，这里补的是同一场事故里两者会一起动：批量变大时，周期时间上升，故障定位范围也随之变宽、MTTR 跟着上升。题干同时给出两个数时，看它问的是「交付」还是「恢复」，不要因为两个都在恶化就随便选一个。 周期时间 → 第一步 · 流动；MTTR → 第二步 · 反馈。
三步工作法
vs
CALMS		 原则 vs 价值观这一层2.1 kp-2-1-1 已经展开，此处不重讲。跨节要记的只有一条：两者都是官方内容、且互不隶属——Blueprint 同时列出三步与 CALMS 五个字母，谁也不是谁的细化，所以「CALMS 是三步的展开」「三步是 CALMS 的 Lean 部分」都不成立。 题干出现「values / 价值观」，答案往 CALMS 走。
约束理论
vs
三步工作法		 官方 v3.4 课程大纲把 The Theory of Constraints 与 The First / Second / Third Way 并列列在 M2 之下；本站在教学上把它挂到第一步，是因为它回答的是「流动卡在哪」。两种说法针对的问题不同，不要用其中一种去否定另一种——这也是本章最容易混的分界，复习时优先确认。 问它解决什么问题：找瓶颈、提升端到端产出 → 约束理论；描述价值流该具备哪三种能力 → 三步工作法。
表中「故障演练」不是 DOFD v3.4 官方考纲术语表中的条目， 它在这里只作为帮助理解混沌工程边界的教学补充； 考试中出现的是官方术语表条目「Simian Army / Chaos Monkey」。 「安全文化 Safety Culture」是 v3.4 课程大纲 M4 的模块子项，但未列入 66 条术语表。 各对概念之间的分界线表述与判据口诀，均为本站教学整理，非官方原文。

⭐ 本章的出题角度
  • 归类题：给一个具体做法或指标，问它属于三步中的哪一步。 干扰项通常把第二步与第三步的描述互换，或者把只服务第一步的约束理论说成覆盖全部三步。
  • 目标题：问某一步的目标是什么。干扰项常写成该步明确反对的行为 （比如「允许已知缺陷流向下游」「用局部优化换全局退化」）—— 看到「反对项被写成目标」直接排除。
  • 定义辨析题：约束 vs 浪费、周期时间 vs MTTR 这类。 干扰项的做法是给出一个本身正确、但描述的是隔壁概念的句子， 所以不能只看「这句话对不对」，要看「这句话说的是不是题干问的那个词」。
  • 排除技巧：凡是需要横跨三步才成立的选项都要格外小心 —— 约束理论、同行评审、混沌工程在本站的归类里各有明确归属， 先确认题干问的那个词到底落在哪一步，再判断这个选项站不站得住。
以上命题角度与干扰项形态的归纳，是本站基于考纲结构与 Bloom 1–2 层级要求所做的教学整理， 不是官方公布的命题说明。本站不复制任何官方样题的题干或选项原文。
